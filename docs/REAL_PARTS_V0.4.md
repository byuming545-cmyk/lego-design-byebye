# 真实 Speed 零件基础 V0.4

日期：2026-10-23。工作分支：`codex/speed-real-parts-foundation`。

本轮建立本地说明书证据、真实原生几何、来源连接、可信状态、频率统计及 Part Lab。没有继续扩展车型生成。旧版手工近似模型不再通过生产入口生成、改造或导出。**可生成与已验证真实零件目前均为 0；本轮未达到“新增超过 64 个可生成零件”的目标。** 已完成的解析基础不代表已完成整套库存、编号映射、装配净空或实物验证。

## 打开网页

安装 Node.js 24.5+，解压本分支 ZIP，在能看到 `package.json` 和 `package-lock.json` 的文件夹地址栏输入 `cmd`。逐行执行：

```cmd
npm ci
npm run build
npm start
```

保持终端打开，浏览器访问 <http://localhost:3001/part-lab>。无需 Rebrickable API Key，也无需 Python。`localhost` 指运行程序的这台电脑；下载源代码并不能直接双击打开网站。

搜索 `3001` 检查真实网格、来源连接点、外包框和验证记录；拖动旋转可看底面。搜索 `element:4666579` 查看说明书观测页码，它目前没有已核定的几何映射，因此没有替代网格。点击“说明书与套装”查看六套装与八份文件状态。

开发运行 `npm run dev` 后访问 <http://localhost:5173/part-lab>。统一预览运行 `npm run preview` 后访问 <http://localhost:3000/part-lab>。

## B. 零件可信状态

当前内置快照实际结果：

| 状态 | 数量 | 范围与含义 |
| --- | ---: | --- |
| catalogOnly | 531 | 附录观测到的 Element ID，尚无设计编号映射 |
| geometryReady | 245 | 独立的 LDraw ID，真实递归原生网格已导入 |
| connectionReady | 195 | 当前支持的 Shadow 语法完整解析且尺寸变换已解决 |
| collisionReady | 245 | 由真实网格导出的保守 AABB；空腔净空未解决 |
| generatable | 0 | 逐件拼接、旋转姿态及碰撞净空校验尚未完成 |

就绪轴会重叠，不能相加；Element 与 LDraw 又是不同编号空间，不能相加当作唯一 LEGO 设计件数量。导入器测试通过，也不会自动把每一个导入零件标为已验证。

## C. 具体来源

- **库存观测**：本地 PDF 原生文本及坐标，逐条保留哈希、页码、编号与数量。未用 Mock、猜测颜色或虚构库存补全。
- **几何**：[Pybricks LDraw 镜像](https://github.com/pybricks/ldraw/tree/c43ed06a128a10ed65675166bf42eb6fd608b9b0)，固定 revision `c43ed06a128a10ed65675166bf42eb6fd608b9b0`。245 个根编号，递归闭包 732 个原生文件，3,173,996 源字节；保留逐文件 SHA、作者、许可和 URL。包内保留贡献者许可与 CC BY 4.0 文档，原生文件保持原字节。
- **连接**：[LDCad Shadow Library](https://github.com/RolandMelkert/LDCadShadowLibrary/tree/9b1131fb1991f8c0bfc072325e4e12f6271aba35)，固定 revision `9b1131fb1991f8c0bfc072325e4e12f6271aba35`，CC BY-SA 4.0。236 个原始文件、90,462 字节；保留许可证、指令行、继承变换、SHA 和 URL。245 个根中 195 完整解析、46 部分解析、4 无连接，共 4,694 个来源点；全部 `physicalVerified:false`。
- **元数据**：LDraw 原生标题、实际 PDF 封面与文字、带页码的观察；用户指定的车型名称与分类单独标明。未获取的官方产品资料保持 null。

几何导入支持 type 1 递归引用、primitives/subparts、嵌套仿射变换、镜像、BFC、三角形/四边形和边线。缺失、循环、路径越界、完整性损坏、资源超限或未支持的纹理会失败关闭，没有手绘后备几何。

连接导入支持实际 `SNAP_CYL/CLP/GEN/INCL/CLEAR` 和受支持的网格/变换。未知选项、非刚性尺寸变换、finger joints 等会保留问题并降为 partial。按源 ID/截面不能识别的圆柱保留为 cylinder，不能仅凭半径声称它是兼容的 bar。两套上游库版本不同，尚需核对模具与配合。

## F. 工作台、导入与可重复报告

`/part-lab` 使用原生三角网格，连接与几何共同采用 LDraw 原生坐标，仅在显示时整体转换 Y 向下坐标。可旋转、缩放、看底面、切换包围盒和来源点。缺几何显示缺失状态。页面展示公/母/未分类标记、源连接类型、方向及源行，展示不等于配合证明。

主要接口：

```text
GET  /api/parts-foundation/status
GET  /api/parts-foundation/parts?query=3001
GET  /api/parts-foundation/parts/3001
GET  /api/parts-foundation/parts/element%3A4666579
GET  /api/parts-foundation/inventories
POST /api/parts-foundation/inventories/import
```

JSON/CSV 本地导入必须有套装与来源；不同编号/颜色系统显式区分。未知备件不计入非备用数量；本地上传一律保留 user-reported，不能通过提交 `verified` 字段升级。重复清单按真实来源和套装去重；同样 CSV 字节导入不同套装分别保存；本地导入的 Element 会同步进入搜索与统计。总统计文档上限 500，新增超限明确拒绝。

原 PDF 整理脚本为 `scripts/import-instruction-pdfs.py`，需要本地 Python 与 PyMuPDF；重新整理附录才需此依赖，运行网站不需要。脚本是整批输出，不能对现有快照只运行一份新文件就当增量合并。详见[说明书报告](PDF_REFERENCE_LEARNING.md)。目前没有浏览器整本 PDF 自动识别/导入或整车重建功能。

运行以下命令可从实际注册表与清单重建统计：

```text
npm run report:parts
```

输出位于 `artifacts/parts-foundation/`，包含 `report.json`、全部 531 个 Element 的频率 CSV、下一批 50 个 Element 映射目标，以及当前为空的 `next-design-parts.json`。本地导入资料默认存入 `BRICKLAB_DATA_DIR/parts-foundation/private/`，不写回有版权的上游源文件或静态快照。

## G. 旧数据审计与硬限制

详见 [PART_AUTHENTICITY_AUDIT.md](PART_AUTHENTICITY_AUDIT.md)。已发现旧手写尺寸、自动反凸点格子、轮毂装饰肋、近似曲面、轮组接口以及不支持库存的占位尺寸。它们仍可供历史回归分析，但不能作为新原生库的来源。

生产 API 默认阻止旧生成、改造、模块修改、撤销和导出，返回 `409 REAL_PARTS_FOUNDATION_REQUIRED`；旧网页的本地 PDF/JSON/BOM 按钮及函数入口也禁用。旧真实库存支持快照不再把手工 supported 提升成 generatable。旧 CLI 默认停止，仅显式 `--legacy-fixture` 供历史算法测试；测试构造参数不会开放给 HTTP 或环境变量。

旧算法未发现运行时动态创建商用零件编号。Mock 中两个明确合成示例编号均不受支持，且完全不进入真实频率统计或真实库。新库未知编号返回 404，没有方块/假风挡后备。
