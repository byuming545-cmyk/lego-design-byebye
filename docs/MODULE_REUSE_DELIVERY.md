## 实际解决的问题

正式生成器现在可以读取有许可和版本记录的现成子装配，通过当前开放接口计算整个模块的刚体安装姿态，再逐件执行正式装配检查，输出包含模块来源的模型、BOM 和步骤。导出的 JSON 重新导入时，会重新检查当前零件权限、连接图和模块配方；上传的“验证成功”声明不能授予权限。

本轮交付的是 **一个套装来源的车头上盖设计、两种提取/适配配方、四个实际生成组合**。它们都使用已有真实零件。本轮没有新增原生零件或生成资格，也没有完成整车。

优先研究的尾翼没有通过当前原生碰撞检查，仍然阻止。转而完成来源证据更充分、能通过现有规则的车头上盖，没有删除尾翼失败记录或扩大配合豁免。

### 安装、占用和多点闭合

1. 读取原始布局，以配方入口实例的逆变换统一到模块局部坐标。
2. 内部装配只接受当前接口求解器能精确恢复的来源姿态。每一次插入仍调用正式引擎，并做原有多接口一致性与占用检查。
3. 对外口来自当前开放且未被内部连接占用的接口；按共享物理端点去重，不把别名当成额外空闲口。核心版 12 口，换件版 8 口，均不是“所有口已实拼认证”。
4. 基座接口与模块入口求得 `T_entry_world`，整体变换为 `T_module = T_entry_world × inverse(T_entry_local)`。所有成员均使用同一个 `T_module`，不单独移动成员补偿误差。
5. 每个候选都重新执行内部及跨基座碰撞、多点和整图检查。失败返回原输入图，不保留半成品。多点成功见生成图中的 10/14 条内部连接边；成员移动 1 LDU 的负例被拒绝。
6. 实例命名与来源命名分开。重复安装同一模块的开发回归使用 3031 基座，得到 11 件、两份不冲突的模块来源记录；公开生成目标本轮仍以一个模块加一个真实基座为范围，不宣称已完成多模块整车搜索。

`GET /assembly/modules` 的 `VALIDATED` 仅指当前内部装配及可用对外接口计算；不会因为查询成功就记入正式生成覆盖。实际覆盖只由交付模型和重导入结果统计。

模块证据另外绑定清单、配方、源文件和 `modulePolicy()`；原生图继续绑定来源快照、引擎、连接和碰撞版本。缓存返回隔离副本；命中仍复核源字节和当前整图。配方更新须更新独立清单 pin、审查并重启；来源、解析器、接口规则或验证套件变化后，旧模块证据不能直接导出/导入为当前成功。不会热写用户模型。

当前只接受经审查的平铺 `.dat` 实例片段，不是任意 MPD 的自动认证导入器；嵌套子模型、非刚体实例和未知身份继续拒绝。公开目标本轮只组合一个模块与一个真实基座。四个安装见证均只有一个对外连接点，未验证悬臂保持力或实物稳定性；下一步应增加基于真实支撑分布的候选排序，不能把本轮数字连接通过解释为适合承力。

## 失败、负例及证明范围

- **来源尾翼**：完整原 section 还有两个 3665b 支腿，当前库没有该身份；正常来源检查时根几何可达，Shadow 根文件返回 404，没有据此补造接口。即使仅取已有八件翼面，在原始姿态下 3666 与 85984 仍被当前实体检查判为 `native-plastic-collision`。保留原坐标、匹配接口、求解姿态、碰撞诊断和版本，见 `negative-cases.json`。这不是“现实套装不能拼”的结论：可能涉及重建姿态、旧模型变体或当前代理解释，原因未判定，不绕过。
- **真实穿模**：先合法安装 11211 到 3001 的指定接口，再尝试在相邻真实口安装上盖。内部构件与 11211 发生允许配合区以外的实体冲突，正式引擎拒绝，输入图逐字节不变。该姿态失败不代表全部基座姿态都失败。
- **权限和完整性**：未知模块/零件、来源字节/清单变化、禁用端口、端口重复占用、重复成员、悬空、1 LDU 闭合偏差、镜像、过期规则和哈希篡改均有回归。16 种模型篡改场景均先重算校验和，再执行当前导入。
- **刚体旋转**：只旋转成员、保留旧连接证书时拒绝；完整旋转成员、模块变换、连接 anchor/axis 后可通过，证明没有把某个世界坐标硬编码为唯一安装。
- **UNKNOWN**：没有修改 UNKNOWN/阻止规则；未知几何、未授权机械接口、安装路径、材料变形、轮组配合和实物保持力不因模块来源而自动通过。现有碰撞未知负例随全量套件继续执行。

## 复现与下一步

使用项目规定的 Node 版本及已安装依赖：

```sh
python scripts/check-module-source.py
npm run evidence:modules
npm run build
npm start
```

网页进入 `/part-lab?mode=assembly`，选择包含零件 3001 或 3020，点击“复用车头模块”，随后可导出 JSON 并在同页验证导入。生成输出默认使用核心版；HTTP 的 `requiredModuleIds` 可明确选择换件版。配方的实际数量决定输出件数，不靠调整显示数量伪造完成。

下一步按收益排序：

1. 用已保存尾翼诊断核对原重建中 3666/85984 的相交位置、实际变体与原生代理；只有找到证据充分的共性解释才修改，不先尝试扩大豁免。
2. 选择能与当前上盖共用基座宽度的来源车尾或座舱模块，复用本轮管线，形成两个不同功能设计的组合；先受现有 32 实例限制验收局部车身。
3. 为整车目标加入模块用途、安装高度和覆盖区域约束。当前成功证明合法安装，不证明自动选到美观、比例合适的跑车布局。
4. 并行于模块路线继续获取真实轮架、轮毂和轮胎配合证据，分开验证最终姿态、旋转净空、安装路径和实物性能；没有这些结果不能称为完整跑车。

新源码约束限于小模块适配，未迁移第三方系统、增加复杂依赖或重新开放旧参数化生成器。
