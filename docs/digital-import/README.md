## 4. 验证范围与失败原因

所有候选使用 `maxInterfacesPerPart=null`，没有按数量放宽规则。发现200组物理接口：155组进入实际夹具测试，136组通过、19组被阻止；另外45组在连接完整性或原生碰撞代理前置检查阶段被阻止，没有声称完成拼接测试。夹具检查项目1,088通过 / 1,107实际执行；被阻止检查是保留的模型限制，不是被忽略的成功条件。

- `11477`、`15068`：原生外部开放边界。
- `18973`、`18974`、`4624`、`3641`、`32054`：原生边界分叉，不能可靠建立碰撞实体。
- `3700`：非平面的开放边界。
- `18976`、`3705`、`2780`：连接资料仅部分解析。
- 已通过件的未开放接口仍有 `compatibility-unknown`，特别是机械连接；不从外形、孔径或一次显示成功推断轴、销、轮胎配合。

本轮没有更改碰撞、求解器、兼容规则、标准生产夹具和生产迁移报告；没有实物拼搭或连续安装轨迹认证。现有生产资格服务测试套件版本绑定等上一轮审计事项没有借本轮改写；新试点每次直接执行当前验证并记录套件版本，不加载旧试点成功标记。

## 5. 流水线、身份和许可防线

`需求 → 固定来源 → 许可/署名 → 精确原生编号 → 几何 → 来源连接 → 完整性 → 装配 → 来源暂存库 → 当前生产资格读取`

- `sources.ts` 只允许已审阅 LDraw/Shadow 版本、URL 和逐文件许可；Studio、BrickLink 网页、未核定镜像不提供公开数字源准入。
- `prepare-digital-pilot.py` 不联网，只接收固定 SHA 的已取得归档；递归选择真实依赖，核对原始 Name 与许可。拒绝覆盖不同内容或生产来源目录，不创建替代几何。
- CLI 在读取源库前核对两份独立钉住的试点清单 SHA；不能靠自写一份带合法外观 URL/许可/哈希的清单冒充上游。`--bundle` 只支持移动同一份已审阅闭包；新修订或新件必须重新审阅。
- 通用装配使用真实原生几何和来源连接，连接解析、软件装配与生产准入分别记录；既有生产资格还须与试点原件的源摘要相同。
- 完整历史候选计划只用于本地研究；候选、冲突或未解决身份请求在精确身份阶段被阻止。
- 新增源库是只读来源入口，HTTP请求和环境变量不能选择它来替换正式仓库；不开放几何写入、许可提升或资格提升 API。

实现路径：`src/parts/digitalImport/`、`src/cli/digital-import-pilot.ts`。现有 `NativePartRepository` 增加显式工具构造参数；生产默认路径及旧体系隔离保持不变。

**本轮分发包只允许包括试点许可源文件、原始许可/署名和经筛选的公开报告。** 使用 `scripts/export-digital-pilot.py` 从清单白名单构造ZIP，逐项核对源文件、清单及许可副本 SHA；不递归复制整个项目。

原始说明书、完整私有需求计划、历史外部映射数据、Studio资源、旧模型/会话和缓存均不进入此包。几何维持逐文件原许可，Shadow源及连接衍生资料按CC-BY-SA-4.0保留署名与许可。

整个开发仓库仍保留上一轮的历史映射审计资料，其独立数据许可未解决。**本轮没有把整个应用宣布为已获全部数据再分发许可的公开部署包。** 后续公开应用部署还需单独核定或剔除历史数据的分发路径。源数据包不会扩大这类数据的分发。

## 7. 重现方式与测试

现成试点源闭包已随开发分支保存，运行导入不需要联网、Python或API密钥。Node.js24.5以上，在项目根目录执行：

```sh
npm ci
npm run import:pilot
```

命令输出逐件结果并重新生成公开报告、当前装配证据和本地私有需求计划。它不修改正式来源或生产资格。`--output`可选择报告目录；未经审阅的新源库会被拒绝。

只有需要从原始归档重建闭包时才需要Python；归档须从获准渠道取得并满足固定SHA：

```sh
python scripts/prepare-digital-pilot.py --ldraw-archive <local-ldraw-archive.tar.gz> --shadow-archive <local-shadow-archive.tar.gz>
python scripts/export-digital-pilot.py --output <new-output.zip>
```

导出器拒绝覆盖已存在的ZIP。开发仓库和许可源数据包用途不同；使用完整应用进行公开部署前，还需核定历史数据的许可和访问范围。

新增测试覆盖来源拒绝、未知许可、缺失署名/许可副本、伪造精确Element、编号/实际根文件冲突、部分连接、过期/空装配证据、独立源清单摘要、生产权限隔离和完整原生闭包。完整单元/API 回归为 **46 个文件、619 项通过，0 失败，89.88秒**；编译预览 **3 项通过，0 失败，32.2秒**，包含构建及类型检查；另有 **6 项 Python 来源准备/分发检查通过**。实际记录见 [validation-results.json](validation-results.json)。

## 8. 后续批量导入建议

1. 先用获准的官方库存/API或官方批量表补足 Element/Design/LDraw 的明确身份链；当前0EXACT不能用更多相似匹配绕过。保留官方授权、速率、条款及许可版本。
2. 每批只增加已审阅的固定源修订与依赖，生成新的清单摘要；保留每次归档与单文件证据。新源或新许可单独审阅，不自动继承本次准入。
3. 优先核验长板、侧向加固与已读附录高频候选；对挡风玻璃、轮拱、轴销/轮组分开记录解析和碰撞阻塞，不为数量增加特例。
4. 对新增`32000`若要进入正式生成，应先审核其限定接口报告，再执行正式源目录/资格迁移；其销孔仍不能随普通凸点一起开放。其他3个新增件先解决原始连接或边界问题。
5. 批量源导入可重复使用此流程；批量生成授权仍需当前来源、验证版本和接口证据。先补生产资格的套件版本撤权测试与历史资料分发边界，再扩大公开部署和自动化准入。
