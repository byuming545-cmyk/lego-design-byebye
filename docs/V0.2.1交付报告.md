## D. Validators

ConnectionValidator 继续从本地目录与实际姿态重建连接图，检查位置、方向、双向兼容及 fit family、接口复用、activeConnections、连通性及伪造接口；本轮导入和存档恢复也重新执行这些规则，不信任 JSON 的连接或通过标记。未将 Bracket、侧面接触或未知接口泛化成合法连接。

WheelValidator 改为读取统一 Registry 中的精确兼容链、姿态、尺寸和接口，保留四轮数量、轮毂/轮胎兼容、轮架/Pin 连接、横向轴线、前后与左右布局、接地、离地间隙及轮胎旋转包络检查。碰撞的机械嵌套例外也从已建模配合关系读取。旋转包络会检查已建模车身/轮拱区域，不代表已经支持未知轮拱的精确几何。未模拟摩擦、弹性、制造公差或实际载荷。

StructuralValidator 在原有模块锚点、刚性底盘、单点承重与轴承例外上增加：

- 长主梁的锚点需沿主跨度展开，避免很多凸点集中一端仍被视为可靠支撑。
- 底盘 Plate/Brick 自身需形成跨越前后轮架的纵向刚性路径，不能借车身或可旋转轮轴代替。
- 同层板/砖接缝需要跨接件实际连接接缝两侧的那两件零件，不能用其他梁的连接冒充跨接证据。
- 区分装饰与承重，小型装饰允许合理单点连接，主要模块仍要求分散支撑。

独立 InventoryValidator 核对真实零件/颜色数量、目录尺寸与用量；CollisionValidator 检查保守实体和精确机械配合例外。任何自动规则失败都不作为有效车辆输出。结构分数是规则符合度，不是实物强度认证。

## E. Physical Validation

**真实实拼数据为 0 次。** 已实现反馈保存、查询和页面表单，尚未收到任何实际用户拼搭反馈。

首次实拼建议流程：

1. 配置 Key、读取手中的真实套装，或准确录入自有散件；核对零件号、颜色和数量。演示库存不能代表手中的某盒套装。
2. 生成通过全部自动校验的候选，在“保存的模型与 JSON”打开保存模型，导出对应 JSON/PDF，记下 modelId、修订号和 digest。
3. 按步骤实际拼搭；记录无法连接、碰撞、松动、轮胎受阻、无法完成步骤或说明不清的位置与零件。
4. 在“实拼反馈”确认已经实际动手，填写拼搭结果、轮组、稳定性、说明书和问题，保存到该精确模型修订。

反馈关联 `modelId + revision + modelDigest`，保存模型结构版本和三项算法版本，标记 `userReported: true`。问题类型为 `cannot_connect`、`collision`、`too_weak`、`wheel_blocked`、`impossible_step`、`wrong_part`、`unclear_instruction`、`other`，可记录 step number、part ID 与文本。

只有用户确认实拼、报告成功、四轮正常、稳定性为牢固/稳定、说明清楚且无问题，反馈推导状态才显示 `passed`；部分成功/失败仍保存详细结果，状态为 `untested`。这是用户自报，不是独立认证。生成、自动测试、导入均不会设置实拼通过；修改或撤销后的新修订不会继承旧修订的 passed。

## F. Persistence

默认根目录是 `data/`，可通过 `.env` 的 `BRICKLAB_DATA_DIR` 修改。原始库存、模型、反馈与 Benchmark 使用本地 JSON 文件；重要输出原子替换，读写失败返回明确错误。

| 目录 | 保存内容 |
| --- | --- |
| `data/inventories/` | 原始 metadata、完整 raw pages、读取时间、normalized 库存、spare/non-spare 与 Speed 支持分类。 |
| `data/models/` | 每个模型的当前存档，含源套装、快照 ID、库存、零件、连接、模块、步骤及校验结果。 |
| `data/models/revisions/` | 按 revision/digest 保留的具体修订，实拼反馈可引用历史修订。 |
| `data/benchmarks/` | 批量验收与缺件频次 JSON/CSV。 |
| `data/feedback/{modelId}/` | 独立的用户实拼反馈。 |

生成与修改自动保存；页面刷新或服务重启后，可在“保存的模型与 JSON”中“打开模型”，浏览器也尝试恢复最后模型 ID。恢复会重新运行当前 Validator。会话撤销栈仍为内存，每个候选最多 12 条，不跨重启保存；没有 Redo、账户同步或数据库。

每个存档包含 `generatorVersion=0.2.1`、`validatorVersion=0.2.1`、`partLibraryVersion=0.2.0-ldraw-c43ed06a`。`candidate.model.version` 是结构版本；`metadata.revision` 是每次保存的修订，锁定、解锁和撤销也会递增；`modelDigest` 将具体模型、库存和步骤绑定起来。

点击“模型 JSON”导出 `schemaVersion: 1` 的 metadata、inventory、candidate；其中包含零件、连接、模块、步骤和自动校验结果。点击“导入模型 JSON”可恢复，但必须通过 schema 和安全上限验证（40 MB、最多 300 个放置零件），尺寸、旋转、接口与支持能力以本地目录为准，重新计算用量、连接、步骤及五项校验。旧 V0.2 无 schema 文件会明确拒绝，请重新生成后导出。

导入创建新 UUID、当前版本和 `origin: imported`；原模型/算法版本记录到 `importedFrom`。所有导入库存降为用户自报，原 snapshot ID 不作为可信数据证据，实拼状态重置 untested。服务端模型 metadata 与导出保持 untested，页面通过独立反馈文件查询具体修订的用户自报状态，文件中自行声明 passed 不产生实拼认证。

## G. Known Issues

- 真实在线库存/生成验收仍为 0，10 套 pending；真实支持率、最高频缺件及轮组失败套装尚无数据。
- Bracket、Mudguard、Windscreen 等仍有大量 recognizedOnly 条目；本轮未新增可生成编号。经典轮组仅识别，完整轮组仍为 1 种。

- 自动规则使用简化几何及结构启发式，可能拒绝现实可行间隙，也无法证明实物扣合、强度、摩擦或拼搭步骤一定成功。
- 实拼反馈是用户自报，当前没有真实记录；旧修订通过状态不会自动迁移。
- JSON 导入仅支持本版 schema 1，旧 V0.2 文件需重新生成；HTTP 兼容快照仍有序列化成本，撤销栈不持久化。
- V0.1 通用模型仍使用原有目录及规则，不新增 Speed 的导入/持久化；无账户、协作或云同步。未开发图片转 LEGO、官方 PDF 解析、F1/Technic、悬挂、电机或自由 AI 重构。

## H. 下一步建议

1. **先跑真实 10 套。** 配置有效 Key 和出站网络，复跑配置清单，检查原始快照、件数/备用件和生成失败阶段，取得第一份真实支持率及频次分母大于 0 的报告。
2. **按真实高频缺件补一个完整结构族或第二轮组。** 从真实频次与阻塞原因选择 Bracket/侧凸点板、轮拱/挡风件或轮轴组合，补足几何、姿态、接口、碰撞及回归，再将 recognizedOnly 提升为 generatable；不凭演示需求扩库。
3. **完成第一轮用户实拼闭环。** 从通过自动校验且零件齐全的具体模型修订开始，收集逐步问题、四轮转动和稳定性反馈，再据该 revision/digest 修正说明书与 Validator。
