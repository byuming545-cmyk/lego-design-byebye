# 保留目标：通过正式模块学习与重组生成 LEGO 跑车

更新日期：2026-11-04。依据用户最新指令，本目标取代之前“生成奔驰 S63”的成品目标；后续任务与旧记录冲突时，以本目标和用户后续指令为准。

## 最终成果

使用来源和许可明确的真实 LEGO 数字零件，学习并复用成熟拼搭设计，自动生成新的跑车整车组合。允许直接采用官方现成的车头、车尾、尾翼、座舱等模块，并通过整车比例、模块选择、布局和局部适配形成新的组合方案。

不要求每个模块都从零发明，也不指定某辆现实汽车作为必须复现的成品。模仿、学习、直接复用模块和重新组合均在目标范围内。保留设计简述、生成参数、候选选择及模块来源，不将借鉴或复用的设计标为完全独创。

## 模块学习与直接复用

- 优先建立车头、车尾、尾翼、座舱、侧裙、底盘和轮组等模块记录；允许从官方套装设计中学习并直接采用有明确依据的结构。
- 每个模块记录来源套装、说明书页码/步骤或数字模型版本、零件清单、局部刚体姿态、内部连接图、外部安装接口及当前验证状态。适用的数据/模型许可与作者信息保留。
- 将参考资料、候选重建、当前装配通过和可参与正式生成分别标记。来源尚不明确的编号、接口和姿态保持待核实，不用图片猜测补成生产真值。
- 复用模块可整体平移、旋转；适配时可选用真实零件替换或增加连接结构，每次修改重新验证。不拉伸模块或零件来强行适应另一车身。
- 官方原方案是设计依据；组合后的模块接口、相互碰撞、占用和整车连接图仍须通过当前正式装配路径。不能从原套装可拼自动推定跨套装组合也可拼。
- BOM、步骤和来源记录要能展开到模块内的真实零件。模块复用不绕过当前接口权限或重新开放旧模型生成链路。

## 保持的技术主线

真实零件库 → 接口语法 → 装配验证 → 正式生成 → 模型、BOM、拼搭步骤 → 导出与重新导入。

- 原始几何、零件身份、接口和配合证据必须真实、可追溯。
- 生成放置只使用刚体变换，不能通过缩放、镜像、变形制造不存在的零件。
- 未知、部分解析及禁用接口继续受限；单接口通过不能扩展为整件全部接口通过。
- 曲面、风挡可按已开放的表面合同参与验证，但不能据此宣称承力、闭合实体或实物稳定性已验证。
- 保留旧体系隔离，不重新开放旧参数化车型生成器。
- 复用组件与数据时继续保留适用许可和作者署名。原创整车设计不改变零件源文件的许可。

## 首个整车验收

1. 输出可辨识的跑车结构：前后轮组、低矮座舱、协调的车头车尾和车身覆盖。具体宽度、轴距和高度以真实零件与接口约束确定。
2. 风挡作为座舱的重要约束，联动宽度、高度、安装点与周边车身；选择有来源和当前权限的合适整体风挡。
3. 轮组与底盘通过真实接口连接，并分别记录最终姿态、旋转净空、安装路径和实物验证状态。
4. 每个实例均能追到准确原生身份及来源；整图、接口占用、碰撞及当前资格检查通过。
5. BOM、步骤、来源与实际模型一致；正式导出后重新导入仍通过当前检查。
6. 只有座舱、底盘或车身子模块时，明确作为阶段成果交付，不称为完整跑车。
7. 输出可追溯的模块组合说明，区分直接复用、经过修改和本轮新生成的部分。

整车组合设计与数字装配通过分别验收。物理稳定性、保持力和实物拼搭没有证据时继续标为未知。

## 既有车型和风挡资料的角色

S63、76924 SL 63、Ferrari 等资料可用于真实零件检索、拼搭学习及模块设计来源。它们不再是必须完整复现的整车目标，某一车型的精确风挡映射不作为所有跑车生成任务的前置条件。
