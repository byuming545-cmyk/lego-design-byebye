# 两车结构修订：操作与复现

本轮是独立结构派生。原 Charger / Golf 外观模型、旧离线包及课程报告保留。连接、安装路径、稳定性和实物拼搭分别判定，不能把完整外观当作可实拼资格。

## 完整应用

Node 24.5+；在仓库根目录操作。Windows PowerShell 使用 npm.cmd。

```bash
npm ci
npm run preview
```

在运行服务的同一台电脑打开 http://localhost:3000/vehicle-generator。云端 localhost 不属于用户电脑，本轮没有公网隧道。

- 车型卡片的“打开已保存示例”仍打开原外观基线。
- “打开结构修订”打开本轮独立保存的结构模型，明确为已保存结果。
- “查看内部结构”可切换内部支承、底板、轮位与座舱；配合俯视和底视检查。恢复完整模型不会改变 BOM。
- 配色、功能分组及细分顺序仍可组合使用。结构顺序每步一件，局部源接口前序与启发式分开记录；独立组件起点不冒充已经接入主体。
- 原生底板图通过只代表其当前数字连接与碰撞检查；轮胎、轮毂、轴、保持力、安装路径和整车实拼仍需单独证据。

如需实际重新求解：先用已缓存资料“生成这款车”，完成后点击“重建底盘与内部支承”。这是实际本地选件、刚体求解和检查，不新增车型研究或模型调用。求解可能需要数分钟；原结果保留。结构输出写入独立 structure-revisions/<SHA>.json，原 job.json 不被改写。链接的 revision 参数可重开并复核当前来源与检查记录。结构派生的配色可在本浏览器保存或导出，不写入原任务的配色记录。

## 离线包

本轮输出目录见 VEHICLE_STRUCTURE_DELIVERY.md。包内 HTML 内嵌两款实际结构模型、原生网格、脚本、样式和图片，不执行新的车型或结构生成。解压后使用个人电脑 Chrome 或 Edge 打开。

步骤模式隐藏零件时，导出配色草稿和顺序 JSON 仍包含完整模型、完整 BOM、父模型哈希、修改与拒绝记录。先选择相同模型再导入。原始外观的草稿不能冒充结构修订的草稿；格式与父哈希不匹配会拒绝。

云端管理员可能阻止 file://，不要更改组织策略。验收分别记录直开结果，以及同一 HTML 经允许的本地 HTTP 加载后停止服务、断网和重新初始化的结果。

## 开发者复现

```bash
node --import tsx src/cli/vehicle-structure.ts 一个尚不存在的输出目录
npm run typecheck
npm test -- --maxWorkers=1
npm run build
npm run export:vehicle-review -- 一个尚不存在的离线目录 --structure
```

CLI 读取真实冻结基线及当前原生库，不按车型名返回整车坐标。它保存基线检查、结构派生、BOM、局部连接图及顺序文档。public/vehicle-structures 是本轮经检查的快照入口，public/vehicle-demos 保持原样。重新生成 CLI 后应检查实际渲染、完整源绑定及未解决项，再更新结构快照，不能只替换图片。

浏览器检查脚本：

```bash
node --import tsx scripts/verify-vehicle-structure.mjs 新浏览器证据目录 本轮单文件HTML绝对路径
```

默认访问本机 3100 端口，STRUCTURE_BROWSER_ORIGIN 可指向同机正式预览。测试读取真实静态模型和原生网格，不模拟新功能 API。API 实际重新求解另行保留记录。

## 课堂快速查看

先打开结构修订，展示完整外观；切到“查看内部结构”，选底盘并查看底视；再进入草稿步骤，播放开头后跳到座舱/车顶。两车都不必完整播放数百步。说明底板数字检查已通过，同时指出轮组与部分外饰仍待接通，不能将草稿称为整车实拼说明书。
