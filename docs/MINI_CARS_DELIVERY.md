# 独立迷你跑车外观工作区

日期：2026-11-05。分支 `codex/mini-car-appearance`，基准 `3cbf8ac`，目录 `/workspace/lego-import-collision`。

## 实际解决的问题

新增独立“迷你跑车”页面，可以直接生成外形完整的六格宽双门小跑车，选择短轴或长轴、车身色和尾翼，旋转查看，保存并导出模型与实际用件 BOM。它复用既有真实几何和三维控件，不依赖旧 Speed 库存、Rebrickable 或特殊透明风挡。

这次交付完整的外观草稿。轮胎轮毂配合、车轴连接、实体碰撞、保持力和实拼说明书没有获得验证，也没有因此修改原正式装配标准。

## 打开方法

安装好项目原有依赖后，预览使用单端口：

```sh
npm run preview
```

在运行程序的同一台电脑访问 `http://localhost:3000/mini-cars`。已有其他端口配置时按实际启动日志访问。开发模式为 `npm run dev`，访问 `http://localhost:5173/mini-cars`。导航栏也有“迷你跑车”，兼容 `#/mini-cars`。

1. 选择短轴跑车或长轴 GT、车身色、方案种子和尾翼。
2. 点击“生成迷你跑车”。“切换车身方案”切换两种真实布局，保留当前配色和种子。
3. 使用斜侧、侧面、俯视或鼠标拖动查看。
4. 保存方案，再从保存列表重新打开。JSON 与 BOM 可分别导出；JSON 也能从本页重新导入。

本分支没有自动推送或部署，旧站点或旧下载副本不会自动包含此入口。

## 现场和范围

初始工作树干净，确为 `3cbf8ac`。阅读适用规范、当前目标、HANDOFF、曲面/碰撞/模块交付和源代码。没有发现适用 AGENTS.md；检查远端没有发现替代该本地实现的更新，从它创建新分支。云环境运行规范沿用既有技能；没有安装新依赖或更改联网配置。

用户最新要求将当前阶段收敛为外观：车身六格、轮组可少量突出、普通黑色件表达窗区、无需内饰与车灯，轮组机械验证延后。以前要求完整座舱及完整实拼准入的主线保留为独立能力，没有用它阻止新草稿显示，也没有撤销其规则。

用户截图用于学习薄底盘、低矮轮廓、黑窗和分层覆盖。没有根据截图重建数字零件、猜隐藏接口或声称复刻原作品；没有复制未经许可的图纸、视频、Studio 资源或第三方代码。

## 页面、生成和保存的独立性

| 层 | 本轮实现 |
|---|---|
| 页面 | `src/pages/MiniCars.tsx`、`mini-cars.css`，独立路由 `/mini-cars` 和导航 |
| API | `/api/mini-cars`，独立 Router，最多 2 MiB JSON，禁用响应缓存 |
| 来源 | `MiniCatalog` 复用 `RealPartRegistry.repository` / `NativePartRepository`；清单和原生文件仍只有原来一份 |
| 生成 | `src/mini-cars/generator.ts`，有限的项目设计布局，不调用旧参数化汽车生成器 |
| 格式 | `bricklab-mini-car-appearance-1`、`mini-car-layout-1`、`APPEARANCE_DRAFT`，使用 LDU |
| 保存 | `<dataDir>/mini-cars/models/`，独立于 Speed、正式装配和用户示例库 |
| 验证 | 来源/布局检查与机械验证分开；碰撞 UNKNOWN、连接 NOT_VERIFIED、实物 false |
| 复用显示 | `NativeAssemblyViewer` 增加可选设计色和视角；不传新参数时保留原行为 |

新模式不创建第二套几何真值，也不写入任何正式资格、连接白名单或装配成功缓存。旧正式模型仍维持 32 实例限制；外观模型独立上限为 128，当前实际方案最大 79 件。128 是文档/资源上限，不是任意 128 件组合的支持承诺。

## 真实零件与布局怎样工作

当前设计集合使用 15 个既有原生身份：

`15068, 18974, 18977, 3001, 3004, 3005, 3020, 3022, 3032, 3039, 3068b, 3069b, 3623, 3710, 66727`。

实际请求只读取所需的集合：没有尾翼时不要求尾翼零件，没有曲面端部时不要求 15068。每次生成、打开和导出会复核当前清单与所需原始依赖，包括已有网格缓存命中时；源文件哈希、大小、许可变化或依赖缺失继续拒绝。

布局过程：

- 窄底盘主梁和六格宽中部板，避免一块宽实板占据整个轮组空间。
- 四个真实 18974 轮拱形成前后轮周外形；轮胎 18977、轮毂 66727 只做源网格外观定位。
- 两种轴距决定车长、窗区、车顶和侧板覆盖范围。
- 普通 3001 与 3039 黑色零件表达窗区；光面板组成车顶，不需要透明车窗。
- 端部使用已有曲面或斜坡，种子决定覆盖选择。可选尾翼使用三个真实零件。
- 所有放置只改变刚体位置和朝向；不缩放、镜像、拉伸或改写原始顶点。

轮位和轮拱位置是项目外观设计，不是新建接口规则或已验证的轮胎轮毂配对表。所有放置保留 NOT_VERIFIED；没有制造连接边。

当前支持两类布局、两类端部覆盖、四种设计车身色及尾翼开关。相同选项、种子和来源可得到完全相同的 ID、姿态、来源和 BOM。尚不支持任意文本指令、联网搜图或指定车型复刻。

|---|---:|---|---|---|

| sprint-white-no-wing | 65 | 6 / 15 格 | 160 / 40 LDU | 斜坡 / 无 |

四个样例均保存后由新服务实例重新打开，内容、颜色、姿态和 BOM 一致；同一 ID 重复保存保持幂等。全部被旧正式模型导入拒绝，没有获得整车装配证书。

BOM 按最终实例的准确原生编号与设计色分组；轮胎、轮毂各四件。颜色可购买性仍未知。源几何根文件、完整依赖、作者、许可、固定版本和逐文件哈希包含在模型中，页面明细提供原始来源链接；这不扩大解释为整个应用的再分发许可。

每例保存模型、BOM、来源、重开模型和验证记录，见 [models/](../artifacts/mini-cars/models/)。生成实例约 3.9–4.3 万三角面，复用网格而非复制新零件几何。脚本计时使用正式基准审计后的热仓库，不当作冷启动或设备帧率保证。

## 视觉检查与证明边界

已在真实 Chromium/WebGL 中检查斜侧、侧面、俯视和手机预览。早期 58/65 件布局在窗区下方留下明显侧向缺口，按真实轮拱端点之间的设计区域补齐侧板及下沿，最终为 68/79 件。修复没有新增或改写零件。初始缺口截图保存在 `experiments/initial-side-gaps.png`，当前结果保存在 `screenshots/`。

自动检查证明：来源完整、刚体变换、四轮布局、六格车身宽、基本包围范围对称、当前生成记录可复现。侧板范围测试防止再次出现已发现的布局缺口。包围范围对称不等于每个三角面的镜像证明。

没有用 AABB 证明实体净空。当前 `collision: UNKNOWN`，`connections: NOT_VERIFIED`，`wheelFit: UNKNOWN`。截图目视检查不能取代实体碰撞、接口闭合、轮组旋转净空、安装路径、保持力或实物认证。第一版仍较方正，端部和侧面细化、连续曲线、车灯与内饰尚未实现。

## 保存、篡改与版本变化

模型内容校验和之外，重新打开还会用当前来源和选项重新生成规范记录，比较来源、姿态、色彩、BOM、状态和版本。修改内容后重新计算校验和，不能授权错误来源、缩放、镜像、假连接或假实物状态。对象字段顺序变化不会误判；自由手动编辑的模型不属于本版本支持范围。

源清单、几何解析器或布局版本变化会导致旧模型需要重新生成；没有静默升级旧记录。

保存使用完整临时文件和排他的同目录链接发布。同一确定性 ID 的同内容保存是幂等的；已有同名记录内容不同则返回冲突并保留原文件。失败校验不会覆盖已保存模型。JSON 文件最多 2 MiB，路径仅接受严格模型 ID，没有访问用户示例目录。
